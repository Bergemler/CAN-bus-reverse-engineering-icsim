# CAN Bus Reverse Engineering with ICSim

A practical cybersecurity laboratory project exploring CAN bus traffic analysis, replay attacks, and signal decoding using the ICSim vehicle simulator.

The experiment was carried out as part of my studies in the **Arqus Joint Master's Programme in International Cybersecurity and Cyberintelligence (MICAC)**.

## Project Overview

The objective ===> investigate communication over a simulated automotive CAN bus, identify messages associated with vehicle functions, and experimentally reproduce their behavior through CAN frame replay and injection.

The project includes traffic captures, custom Python analysis tools, and a technical laboratory report.

## Technologies and Tools

- Ubuntu / WSL
- SocketCAN (`vcan0`)
- [ICSim by zombieCraig](https://github.com/zombieCraig/ICSim)
- `can-utils` (`candump`, `cansniffer`, `canplayer`, `cansend`)
- Python 3

## Methodology

The experiments were conducted in five stages:

1. **Baseline Analysis** — Recorded and characterized background CAN traffic, including message frequencies, transmission intervals, and payload variability.
2. **Differential Analysis** — Compared idle recordings against traffic generated by turn indicator actions.
3. **Replay-Based Bisection** — Progressively filtered and replayed CAN IDs to isolate the message responsible for the left indicator.
4. **Payload Decoding** — Investigated individual bytes and bits by manually injecting CAN frames.
5. **Additional Functions** — Examined speedometer readings and vehicle door-lock states.

## Key Findings

| CAN ID | Identified Function | Findings |
|---|---|---|
| `0x188` | Turn indicators | Bit 0: left; bit 1: right |
| `0x244` | Speedometer | Numeric field associated with displayed speed |
| `0x19B` | Door locks | Four-bit lock-state field in payload byte 2 |

The initial idle capture contained **36 unique CAN IDs**.

Replay-based bisection successfully isolated CAN ID `0x188`. A filtered recording containing only 46 frames with this ID was sufficient to reproduce the left indicator's behavior.

The speedometer and door-lock functions were also tested through manually constructed CAN frames.

The exact numerical scaling of the speed signal was not fully established.

## Python Scripts

| Script | Purpose |
|---|---|
| `idstats.py` | Analyze CAN IDs, transmission intervals, and payload variability |
| `diffids.py` | Compare CAN IDs and payloads between two captures |
| `filterlog.py` | Filter CAN logs by one or multiple CAN IDs |

Example usage:

```bash
python3 scripts/diffids.py captures/idle1.log captures/left.log
```

```bash
python3 scripts/filterlog.py captures/left.log /tmp/left_188.log 188
```

The current `idstats.py` analyzes `idle1.log` using its configured filename. From the repository root, run:

```bash
cd captures
python3 ../scripts/idstats.py
```

## Security Considerations

The experiments demonstrate how CAN messages can be recorded and replayed when message origin and freshness are not authenticated.

All testing was performed using the **ICSim simulator and the virtual CAN interface `vcan0`**.
